# leak-audit.md — 数据隔离审计判定口径
> 引用位置：SKILL.md §S2；加载时机：发布前审计与判定 WARN 项时读。

## 1. 为什么要审计

对外发布是**不可逆动作**：一旦推送，密钥会被 GitHub 抓取（公开仓库数分钟内就会被扫描机器人
利用）、个人路径与内网信息会永久留在 git 历史里。**审计必须发生在 `git init` 之前**——
事后删除文件不等于删除历史（`git filter-repo` 是代价高昂的补救）。

## 2. 三级判定

### BLOCK（必须修掉，零容忍）

| 类别 | 示例 | 处置 |
|---|---|---|
| 真实 token | `ghp_…`（classic PAT）、`github_pat_…`、`gho_…` | 吊销该 token → 从文件删除 → 复扫 |
| 云/AI 密钥 | `sk-…`、`AKIA…`、`xox…` | 同上 |
| 私钥 | `-----BEGIN … PRIVATE KEY-----`、`*.pem`/`*.key`/`*.p12` | 从树中移除并确认未进历史 |
| 硬编码密码/API Key | `password="…"`、`api_key: "…"` | 改为环境变量/占位符 |
| 敏感文件 | `.env`、`*.keystore` | 移出 + 写入 `.gitignore` |
| 超大文件 | 单文件 > 5MB（GitHub 硬限 100MB/文件、建议仓库 < 1GB） | 移出或改用 Releases/图床 |

### WARN（逐条人工判定，能改就改）

| 类别 | 示例 | 常见处置 |
|---|---|---|
| 个人绝对路径 | Windows 盘符下的用户目录（Users 后接真名）、类 Unix 家目录路径 | 改为相对路径；确需示例时用正斜杠占位形式（正斜杠写法不会触发扫描） |
| 邮箱 | 真实工作邮箱 | 提交身份与文档统一用 `…@users.noreply.github.com` |
| 内网地址 | `10.x`、`192.168.x`、公司域名 | 替换为 `<internal-host>` 或删除 |
| 手机号/真名 | 文档、示例数据中 | 替换为占位符 |

**豁免口径**：环境类文件（如 `environment-notes.md`）中确需保留的本机实测路径，必须逐行标注
**「本机实测，按需替换」**——审计脚本会将其降级为 INFO，不阻塞发布。

### INFO（确认即可）

- `node_modules/`、`__pycache__/`、构建产物目录出现在树内 → 确认已被 `.gitignore` 覆盖；
- 脚本自身包含的密钥**匹配规则**（正则字符串）不会命中真实密钥，属正常。

## 3. 执行方式

```bash
node scripts/leak-audit.js <项目目录>     # 退出码 1 = 有 BLOCK
```

审计结论写入项目内 `docs/LEAK-AUDIT.md`：日期 + BLOCK/WARN 清单 + 逐条处置 + 结论（通过/不通过）。
**留痕是给未来的自己看的**——三个月后有人问"这个仓库发布时审过什么"，答案为文档。

## 4. 数据隔离的边界（脚本之外的操作纪律）

- **只操作目标项目目录**：不遍历、不复制其他目录；不读用户主目录下的私密文件；
- **token 生命周期**：只在内存/环境变量中存在，用于一次建仓+推送；脚本结束即失效；
  任何时候不得写入文件、`.git/config`、命令行可追溯的历史（如 shell 历史中的明文）；
- **不 force push**：远端已有内容时以用户确认为准，禁止覆盖他人/历史提交；
- **发布后复扫**：推送完成后再次跑一次审计（防止漏网），并检查 `.git/config` 无 token。
